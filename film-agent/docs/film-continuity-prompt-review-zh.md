# 连续性提示和链路差距

## 由实片回推提示

白猿交册原镜的提示把体形和袖口裁切都列成开场构图。新版把构图、轮廓、服装及道具本体明确分开，并按发生时间排动作。每镜只描述本镜能看到的材质、声源和变化。H3 正向提示当前实物如何保持或移动。把彩色光的变化与面料本色分开。画外母题没有当前触点时留在导演记录。

SceneWeave 2.0 给每拍绑定一个可见的连续性对象。同一事件中，该对象再出现时，应接住已确认的出点。状态变化须有画内触发。分镜通过拍点号调取动作、对白和状态，首帧只读取开场状态，生成提示同时读取进入、变化及收镜。修改过的物件交接按动作阶段写，反打可承接状态和人物反应。

既有镜头回放和继续生成时可读取原请求。新结构化派单明确标记提示版本，现场只使用已核对的素材。设计上的“保留布色”用于提示和检查，实际是否保持由真实连续帧确认。

## 应用的资料

- MiniMax H3 的 Ref2VA 规范按参考对象定义职责，并在保留关系里陈述保真范围。用在 Harness 的实际 H3 请求。 [官方 Ref2VA 指南](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_ref_en.md)
- Runway 的图生视频提示把输入图已有的视觉信息与需要生成的运动分开，用正向语言写清行为和时间。用在动作编译和本镜造型信息的范围控制。 [Runway 图生视频指南](https://help.runwayml.com/hc/en-us/articles/48324313115155-Image-to-Video-Prompting-Guide)
- Drama Skills 的美术设定、分镜和审片分工用于划清三层。Performance Direction 与 Editing Montage 用于把接触、重心、反应和接剪做成可复验的事件。技能出处记在规则说明，实际生成继续使用 H3。 [Drama Skills](https://github.com/zenstory-ai/drama-skills) · [Performance Direction](https://github.com/calesthio/generative-media-skills/blob/main/skills/production/creative-direction/performance-direction/SKILL.md) · [Editing Montage](https://github.com/calesthio/generative-media-skills/blob/main/skills/production/post-production/editing-montage/SKILL.md)

## 与 Harness 的差距

| 路线 | 已有可运行能力 | 当前缺口 |
| --- | --- | --- |
| Harness 生产 | 原著取舍、导演审阅、取真实参考、用人看片、切点与同期核对、定点重拍、合成和交付。 | 关键取舍依赖操作者的看片与经验。观察到的故障还需要写成带证据的案例，逐条迁入系统和验证。 |
| SceneWeave 2.0 | 有原著证据的台本、白话对白、动作拍点、连续性锚点。可把台本约束传到首帧与视频提示。 | 缺对实际生成像素与声音的观察。状态来自规划。分镜的锚点数量有限，且同一事件内的校验强于跨场、跨时空。不能自己选取已通过的出点帧或判断原生口型。 |
| Lotus 宣传片方法 | 全书取材、剧透边界、可保存的节拍、单独审稿和配乐起势。 | 评审读计划及文字。成片上的实际音效出入、停顿和演员反应仍须用实际素材验。对五分钟以上单故事也不能用预告片的省略规则覆盖。 |
| Morpho 网页流水线 | 自动分镜、参考图、H3、声音后期、选择性多模态审核、实剪切点与工程。 | 网页 H3 仍有独立的提示构建路径。部分低风险镜只过媒体解码，没有独立识别穿帮。SceneWeave 的锚点未直接变成 DSW 人工拍摄单里的全对象状态、图像裁切和参考图预检。 |
| DSW 生产 Agent | 统一队列、任务状态、原片回传、CPU 合成、音画证据和返修建议。 | 台本出队和渲染入队之间仍需要提供实际参考与验收动作。出现问题后能检索经验、提出返修，成片放行和定点返拍仍依赖确认。结构化拍摄单和裸提示都存在。裸提示只按原文件发送。 |
| 代码生成和 OpenFilm | 精确位置、触点后效果、叠加图层、字卡、字幕、剪辑工程与混音。 | 它们的优势在确定性时间线。细腻角色表演、可信走位和实际原声仍需要可用底片或成熟动作系统。合成依赖跟踪、遮挡和光色匹配，不能推断一个失败拍摄的真实接触。 |
| 本地音频和 CPU 审看 | 可独立做转写、对白窗口、对位、降配乐、响度和工程。 | 转写一致无法证明嘴部、人物归属和时机正确。声音中的碰撞或快门也必须对到真正的画面触点。 |

## 实拍对照

《镜花缘》白猿交册采用原来四张参考图。A 与 B 的请求回执中仅提示词指纹不同。两条为原生 1536×864、24 fps、141 帧。ComfyUI 历史记录两条使用种子 62197421 和 20 步。A 是保存有实际请求的旧试片。B 一起测试参考属性分工、稳定材质、按时间排列的状态以及动作口令。

| 版本 | 画面证据 | 验收 |
| --- | --- | --- |
| A 原提示 | 2.67 秒文人右手才靠近。3.17 秒两边接触同一册。约 4.17 秒离开手的蓝册突然回到画面左端，原片后段再提笔。 | 早段接触可用，连贯移交到提笔不通过。 |
| B 参考分工与状态提示 | 书、浅色纸和袖口后段较稳，竖起的笔也可辨。首帧文人已碰到书。2.67 秒书移动回白猿侧，文人空手。 | 交接方向错误，不能作这场的接册镜。 |
| C 只拍接册 | 首帧右手和书明确分离。1.46 秒掌心到书底；2.88 秒白猿还扶着；3.92 秒书留在文人右手。5.71 秒仍是同一本书和同一持有者。毛笔全程在案上。 | 该镜主要动作通过。首帧书左侧接近裁边，和下一镜起笔的成片接点仍需另审。 |

C 沿用相同素材、画幅和种子，并删去提笔这个独立动作。它检验的是拆镜及清楚的身体支撑，不能当作单个语句的消融结果。三条试镜均保留原请求和本地视频。

## SceneWeave 实跑

用 Luna 在四个小用例比较上一版和新版。三组两边都出稿，交给只看正文的独立文字审稿。旧版交册的空间关系写得更清楚，新版登船写清了左手先触栏再承重，并区分素帆的材质和船灯照明。新版取字把接触、夹住、拉离与读到新句意写成连续阶段。扣盖和快门的旧版未生成通过校验的场面，不计入胜负。取字的初次响应确有乱码，重放原响应并用同一网关定点补修后参加对照，保留了演员、道具和光线的原方案。

程序回归验证能拦截同一事件的道具跳位、重复生成一次状态变化和缺少触点的状态改变，也验证了上一个场景的全片母题不会被编进目前首帧和视频提示。共 38 项测试通过。本轮的实拍只涉及一处交接，无法推算全片穿帮率。

## 接下来应补的关键缺口

优先让 SceneWeave 的状态、浏览器分镜和 DSW 的实际参考及拍摄单共用一套对象 ID。上一镜经过画面审核的出点应成为下一镜启动的条件。给接触、复验、遮挡后重现、换装及换时空选最短的阶段，按照触点和结果做验收。可由 CPU 解码和数据校验完成的检查在派单前完成，只有身份、动作、口型等需要看真实画面的风险使用短窗审片。
